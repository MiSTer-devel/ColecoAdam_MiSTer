# MiSTer hardware test kit

Scripts, MGL files and test cartridges for testing the core on a DE10-Nano. First used for branch
`adam-accuracy-fixes` on 2026-09-13, then for the memory expander on 2026-09-19. The checklist and
the results are in `HANDOFF.md`.

## Layout on the MiSTer

| Repository path | Copy to | What |
|---|---|---|
| `_AdamTests/*.mgl` | `/media/fat/_AdamTests/` | One MGL per checklist item; appears as a menu folder |
| `_AdamTests/run_test.sh`, `run_suite.sh` | `/media/fat/_AdamTests/` | Load an MGL and take screenshots; run the suite |
| `config/AdamT_*.CFG` | `/media/fat/config/` | OSD settings for each test set name; generated by `config/make_cfgs.py` |
| `banktest/banktest.col`, `banktest/uppertest.col` | `/media/fat/games/Adam/_accuracy_tests/` | Expander bank walks, lower and upper 32K window |
| `vramtest/vramtest.col` | `/media/fat/games/Adam/_accuracy_tests/` | Too-fast VRAM write test |
| `vkbd.py`, `vpad.py` | `/media/fat/` | Virtual keyboard and Xbox 360 pad through `/dev/uinput` |

The MGL groups are `A*` ADAM mode, `C*` console mode cartridges, `P*` PowerPAINT at each expander
size, `R*` RAM and bank tests, `S*` spinner and roller, `T*` T-DOS, `U*` the upper-window bank walk.

Media goes in `/media/fat/games/Adam/_accuracy_tests/` under the short names the MGLs use:
`dkjr.dsk`, `trollstale.ddp`, `blank_tape.ddp`, `frogger.col`, `cosmo.col` and so on. The `.col`
files in the table above are generated - run the `make_*.py` beside each one. The older
`ramtest.rom`/`banks.rom` pair that the `R1`-`R6` MGLs load comes from
`verilator/compare/tools/adam_exp_ramtest.py`; `banktest.col` supersedes it, reporting a bank count
rather than one pass/fail colour.

**Every MGL names the core it loads**, currently `_Computer/ColecoAdam_20260922_refresh`. That one
line is what to change when testing a new build, and it is easy to forget and then wonder why a fix
did not appear:

    cd hardware_tests/_AdamTests
    sed -i '' 's|ColecoAdam_20260922_refresh|ColecoAdam_NEWNAME|g' *.mgl

`C6` is deliberately excluded: it loads the stock `_Console/ColecoVision_20260603` core, to compare
Gauntlet against a core that is not ours.

## How the MGLs work

- Each MGL sets `<setname same_dir="1">`, so its OSD settings come from its own
  `config/<setname>.CFG` and the normal `Adam.CFG` is untouched.
  - A CFG is 16 raw status bytes, little endian, and is the same `status` word the OSD sets.
  - Do not hand edit them: `config/make_cfgs.py` generates them from one bit-layout table, which
    is the place to look for and to fix the layout. Keep it in step with `CONF_STR` in
    `ColecoAdam.sv`.
  - Expansion RAM is **`status[19:17]`** - 0 64K, 1 256K, 2 512K, 3 1M, 4 2M, 5 none. It used to
    be `status[5:4]`, and moved when the larger cards needed a third bit, so **any `.CFG` written
    before 2026-09-19 selects 64K whatever it used to say.** Regenerate rather than reuse.
  - Byte 1 bit 4 selects Console mode (`status[12]`).
- The cartridge entry in `CONF_STR` is a plain `F`, so its MGL `index` is 0. Main_MiSTer matches
  `index` against the digit after `F` or `S`.
- Disk and tape boots add `<reset delay="2" hold="1"/>` after the mount. The ADAM only looks for
  boot media at reset, and an MGL mounts after the core has booted.

## Running from a PC

    ssh root@MISTER 'echo "load_core /media/fat/_AdamTests/A2 DK Jr disk boot.mgl" > /dev/MiSTer_cmd'
    ssh root@MISTER 'echo screenshot > /dev/MiSTer_cmd'
    ssh root@MISTER 'sh /media/fat/_AdamTests/run_suite.sh'

`run_suite.sh` saves named screenshots in `/media/fat/screenshots/AdamTests/`. Its tape read-back
step expects `blank_tape.ddp` to hold the file saved by an earlier tape save run.

## Things to know

- The ADAM smart keys I-VI are F1-F6, and STORE/GET is Page Down (evdev code 109).
- On the Xbox 360 pad mapping, `vpad.py a` is the ColecoVision right fire button.
- Screenshots of the RAM test cartridges came back stale: byte-identical 960x90 captures of
  SmartWRITER from 3 s to 20 s after loading. Judge those tests on the monitor instead. The other
  tests' screenshots were live.
- The MiSTer has no `pkill`.
